# Windows Nannou LUT provenance follow-up

The [prior evidence](NANNOU-LUT-NOTICES-WINDOWS-20261113.md) identifies the exact Bevy AgX and Blender-derived KTX2 bytes in the Windows pilot. Bevy introduced the tables in [PR 7594](https://github.com/bevyengine/bevy/pull/7594) and later changed them in [the KTX2 update](https://github.com/bevyengine/bevy/commit/489818930b7ec268455fe371b3c5b0fb1c0c46c3). Its pinned conversion instructions name a specific [AgXc PNG](https://github.com/MrLixm/AgXc/blob/898198e0490b0551ed81412a0c22e0b72fffb7cd/obs/obs-script/AgX-default_contrast.lut.png), Git blob `74e27cc28290c4ef9e69f5a441dfcf6f047950a4`. The pinned AgXc recursive tree has no license-, copying-, copyright- or notice-named file; its README calls the project a fork of [AgX](https://github.com/sobotka/AgX). The AgX upstream tree at [revision 1ba3230](https://github.com/sobotka/AgX/tree/1ba3230e6f2c825003d9e139750edd233b6a906e), the latest returned by the commit query before the pinned AgXc revision's 2023-01-15 author timestamp, likewise has no such named file. This comparison does not prove that revision was the fork's source or that no other grant exists. We did not reproduce the PNG-to-KTX2 conversion.

Bevy's instructions describe generating a stimulus and exporting through Blender's Filmic sRGB transform, but do not identify the Blender version or exact underlying configuration. As historical context only, Blender [3.4.0's color configuration](https://github.com/blender/blender/blob/175bd3820151bf9973198daa92f3fe2035f02102/release/datafiles/colormanagement/config.ocio) credits Troy James Sobotka and others for Filmic and refers to an `ocio-license.txt`. Its [OpenColorIO license file](https://github.com/blender/blender/blob/175bd3820151bf9973198daa92f3fe2035f02102/release/license/OpenColorIO.txt) contains a Sony Pictures Imageworks copyright and BSD-style terms. Neither finding proves that 3.4.0 was used, that the OpenColorIO software notice covers the generated LUT, or that a particular license applies to the resulting table. The exact source configuration, rights and attribution remain unverified; generating data with Blender alone does not establish a GPL obligation.

The current locked offline Windows feature graph was inspected with `cargo tree --locked --offline --target x86_64-pc-windows-msvc -e features -i bevy_core_pipeline`. It shows `nannou_draw@0.20.0` enabling Bevy's `tonemapping_luts`; its [exact upstream manifest](https://github.com/nannou-org/nannou/blob/b699dc67d3670090d46531e9380676ddbac6dcfb/nannou_draw/Cargo.toml) requests that dependency feature unconditionally and notes that the default Tony transform samples a LUT. A top-level default-feature switch cannot negate an explicitly enabled dependency feature. A dependency change or replacement would need separate gameplay and rendering validation; none was made here. Lockfile SHA-256 is `91432f25df84ca28c098e84bef6b01ea4cb3912cb27cedf8c1d2f157cf9f8bb6`; raw feature output SHA-256 is `0b5f4c61c985c54724ef50f9fc0814001696ce79bb71e1c58f70e3b690c570e4` and is retained locally in sibling directory `nannou-lut-provenance-windows-20261113`.

The previously recorded package candidates were not modified. LUT rights, source-specific attributions, the Noto font discrepancy, remaining dependency notices, system libraries and release qualification remain open. This is not legal clearance and no public release was made.
