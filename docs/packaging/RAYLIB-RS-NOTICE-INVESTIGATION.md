# raylib-rs 6.0.0 notice investigation

2026-11-13, Omarchy ARM64. The Linux notice scan reported `raylib` 6.0.0 as the one package in the `pong-raylib-rs` resolved graph without a conventionally named notice file. Its cached crates.io archive SHA-256 is `74b6057eb69bc6ac196260f5751a9bc69d69a445174d288ad87b9f6cefecd88c`, matching `experiments/raylib-rs/Cargo.lock`. Its manifests declare `Zlib`; `.cargo_vcs_info.json` records repository revision `2b0b3e355a911325058544523d0b5845edbbbc55` and subdirectory `raylib`.

The published archive has no standalone license file. Its source files `src/lib.rs`, `src/ease.rs`, `src/prelude.rs`, and `src/core/math.rs` contain copyright and permission notices. The first credits the raylib-rs team; the other three credit Paul Clement. Each of those four complete files was fetched through the connected GitHub app at the exact recorded revision and compared byte-for-byte with the cached crate; all matched. For example, [upstream lib.rs at the recorded revision](https://github.com/raylib-rs/raylib-rs/blob/2b0b3e355a911325058544523d0b5845edbbbc55/raylib/src/lib.rs) has SHA-256 `ede8d8a5446ea278d1a91171c0a09a23623b627c3dd1188a072e4d0fd02799b4` in the cached crate. A search of the crate's `src` for copyright, permission, or license references found those four files. This is a bounded text search, not a full legal audit.

`cargo tree --offline --locked --manifest-path experiments/raylib-rs/Cargo.toml --target aarch64-unknown-linux-gnu -i raylib` confirms the target graph contains `pong-raylib-rs -> raylib 6.0.0`; this is not proof of linked binary contents. The present notice collector scans notice-like filenames or explicit Cargo license files, so it does not collect these source headers and still reports this package as missing. A future reviewed collector could include identified source notices with exact-version provenance; do not silently substitute generic text or clear the package as distribution-ready. The separate `raylib-sys` native code, bundled libraries, system dependencies and other obligations still need review. No package, dependency or system configuration was modified.

## Audited collection pilot

A narrowly scoped collector rule now includes the original leading comments from the four verified source files only for registry `raylib` 6.0.0. It verifies each complete source file against its pinned SHA-256, enforces package-root containment and rejects symlinks before extracting the comment. A missing or changed audited source fails collection. Synthetic tests cover exact preservation, whole-file tampering, path escape, symlinks, malformed headers, and version/source selection; the notice and portable-package test files pass on Omarchy. These checks do not establish the adequacy of all notices.

Fresh offline locked Cargo metadata filtered to `aarch64-unknown-linux-gnu` resolves 50 packages with no missing discovered notice files after this rule. The generated notice text SHA-256 is `c11c08a71048de701d217dd32d6853cb33948a5cd00a1c8278464924de7eadf4`. An unfiltered all-platform scan still reports `r-efi@6.0.0` as missing; zero missing for the filtered graph must not be generalized to all targets.

A local notice-bearing archive was created using the previously qualified raylib binary (SHA-256 `ec7b669b76b8dacfb4634dbbfc7caccbe85cb37d9952518e93b1225e807d0f07`, built at `971319ea96bb509248e2bb5b2905db0a777c1f10`). Archive SHA-256 is `d99634bc5829f3ad7985ab1291a72b7d3f4be3e064b4d64d2fffcc4d2878fea7`; all six listed files passed `sha256sum -c` after separate extraction. Archive, extraction and notice outputs are retained under `/tmp/pong-raylib-notice-*20261113*`. The earlier gameplay replay was not repeated or superseded.

This is a local archive and source-notice preparation check. It is not legal clearance, a complete native/system dependency review, a clean-machine installation or a public release. The original binary and prior evidence were preserved.
