## Audio source and isolated reduction candidate

The retained prior Mac raylib-sys build log reports miniaudio and WAV, OGG, MP3, QOA, XM and MOD support enabled. The cached raylib-sys 6.0.0 archive checksum and pinned submodule provenance are described above. At raylib revision [dbc56a8](https://github.com/raysan5/raylib/tree/dbc56a87da87d973a9c5baa4e7438a9d20121d28), Git blob hashes of cached raudio.c and eight included audio files match the upstream copies: miniaudio.h, dr_wav.h, stb_vorbis.c, dr_mp3.h, qoa.h, qoaplay.c, jar_xm.h and jar_mod.h. The implementation includes these conditionally under the relevant format switches. Their inspected notices describe miniaudio, dr_wav and dr_mp3 as public-domain-or-MIT-0; stb_vorbis as MIT-or-public-domain; QOA and qoaplay as MIT; jar_xm's original libxm notice as WTFPL v2; and jar_mod contains both a public-domain heading and a WTFPL v2 notice. These selected notices are not a complete per-file, embedded-code or legal audit. The prior executable's nm output contained no matches for a bounded list of audio/decoder symbol names; that does not prove all audio code absent.

An isolated experiment copied the raylib project and shared crates, kept the locked dependency versions, disabled raylib default features and explicitly re-enabled the prior default features except USE_AUDIO, SUPPORT_MODULE_RAUDIO and WAV/OGG/MP3/QOA/XM/MOD. The first attempt failed because the copied project lacked scenarios/smoke-v1.txt; after copying that file, offline locked ARM64 Release build succeeded and five frontend tests passed. CMake reported Audio Backend: None and its cache records those eight switches OFF. CMake still compiled raudio.c.o; nm showed only a local text marker in that object, not audio functions. A bounded search of the candidate binary for selected audio/decoder symbol names returned zero matches; this is not a complete binary audit.

The candidate executable SHA-256 is 09d3f0101a8343e5c3c55b748f22815cec91eb158a76944e23520356133802b9, and the isolated manifest SHA-256 is 02a56cee9db146083e25075755a71514913a5f568a7f357729d11437716b7550. Its native scripted run exited 0; after filtering mixed raylib logs, all 13 JSON records matched the contact-timing reference and six app-owned PNGs were produced. The captures were not visually inspected. This is model replay, not real key input. Artifacts remain under /tmp/pong-raylib-noaudio-review-20261113-v1, /tmp/pong-raylib-noaudio-target-20261113-v1 and /tmp/pong-raylib-noaudio-run-20261113-v1; original targets and binaries remain intact.

This feature set is a promising Mac-only reduction candidate, not an adopted source change or release. Native interactive behavior, other platforms, assets, remaining codecs/native code, system licenses, notices and complete feature equivalence remain unverified. The source notices reviewed here did not identify an LGPL/GPLv3/MPL audio component, so the experiment is risk reduction rather than a demonstrated fix for such a finding.
