# SDL3 focus/resume gate — Omarchy, 2026-11-13

SDL3's focus-loss handler paused and cleared the application but did not reset its polling gate. If a resume action occurred before the next movement sample, a still-held direction could remain active. The focus-loss handler now also marks the gate as not previously playing; the next sample suppresses held directions until release. A regression reproducing that event ordering failed before the change and passed afterward, including held, release and fresh-press samples. All 10 locked offline SDL3 tests passed, and a debug build passed (SHA-256 `e1c54aedea5c9508d15930e0b3082d8b02053bb48b6c1fb05d8b430f3d7274dd`). Source Git blob: `3a9965738175a3c4b1d7a5e2b02c8cf29a1b15e6`.

A bounded source review found Bevy resets its gate when it samples an unfocused window, Blue Engine samples its gate as paused when unfocused, and Macroquad passes its focus-loss flag into its gate even if play resumes in that sample. Their existing locked offline suites passed on Omarchy (Bevy 6, Blue Engine 8, Macroquad 6). This is not proof that the operating system delivers every focus transition: in particular, the polling checks depend on observing the unfocused state. Source Git blobs respectively `7494de30094aed31d01240f4f80d62f82e491de7`, `474a26c4c584544d8b5b5708066e0ecc2a1482ef`, and `85381e00aa9298ff1f8be166bb1b7b983b0639df`.

The SDL test exercises the handler and gate directly; real window focus transitions, physical held keys, rendered replay, other platforms and release qualification remain unverified. Existing artifacts were retained.
