# Dioxus package-local library path guard

The [package-local libxdo launcher](DIOXUS-RELEASE-XDO-OMARCHY.md) prepends the extracted package directory to `LD_LIBRARY_PATH`. On Linux that variable accepts colon and semicolon separators: either character in the directory name splits the intended path into multiple loader search entries. The previous launcher accepted such paths; a focused test using an executable fixture failed before the correction. This could cause a launch failure or search a location the user did not intend.

The launcher now rejects a package directory containing either separator before starting the executable and tells the user to move the package. Spaces remain supported. The generated guide states the same constraint. Regression checks cover both separators, normal launch, the manifest, incorrect dependency archive and profile validation; the local-xdo, Linux portable and notice-bundle Node test files pass. The guard concerns the package directory inserted by this launcher; it does not sanitize a pre-existing user-supplied `LD_LIBRARY_PATH`.
