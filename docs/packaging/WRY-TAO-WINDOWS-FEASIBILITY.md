# Windows Wry/Tao dependency feasibility probe

This bounded alternative investigation follows the [Tauri parser feature analysis](TAURI-WINDOWS-PARSER-FEATURES.md). A separate task-local Rust fixture used `wry = '=0.57.2'` and `tao = '=0.37.2'` with their default features, the same versions visible in the inspected Tauri stack. It constructs a `wry::WebViewBuilder` value and refers to a Tao window type; it does not create a window or WebView, load content, provide IPC or alter either Pong desktop wrapper. The fixture's Cargo manifest declares MIT for its own tiny source.

On Windows MSVC Rust 1.99.1, the fixture generated a new lock offline and passed locked offline `cargo check`. Windows-filtered locked Cargo metadata contained 81 resolved nodes, no missing Cargo license declarations and no expressions containing LGPL, GPL-3 or MPL. The [path-free declaration list](wry-tao-windows-probe-licenses-20261113.json) has SHA-256 `fcf3fc4f5f9e51f06110c0606af0b857f1b11b2c5a4a8d1b713d08b275500821`. Wry declares `Apache-2.0 OR MIT`, Tao declares Apache-2.0, and the resolved `webview2-com` and `webview2-com-sys` crates declare MIT. The fixture lock SHA-256 is `ebca40a7283cf10b9a3faee827c0c28f96e69d4d177d2eb34d0af7625bd9b0b0`. Metadata is a graph screen, not evidence of complete source, linked-code, WebView2 runtime or system-library licensing.

This demonstrates a narrower dependency graph can compile on this Windows host; it is not a drop-in Tauri replacement or proof that either Yew or Leptos desktop application works. Any future actual implementation must establish an equivalent secure content origin, CSP, navigation and command boundaries, asset handling, scripted export validation, window lifecycle, input and platform behavior before it can replace the current Tauri path. No security handling was bypassed or weakened. No WebView, desktop interaction, browser test, packaged executable, clean-machine check or release was performed. Exact WebView2 runtime terms, third-party notices, target-specific binary linkage, other platforms and the owner's strict license constraint remain unqualified.

Fixture manifest, source, lock, raw metadata and target remain under task workspace `wry-tao-windows-license-probe-20261113`; raw metadata contains local paths and is not published. Existing implementations and artifacts were preserved.
