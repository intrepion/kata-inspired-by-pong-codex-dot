# Web non-pointer movement activation — Omarchy, 2026-11-13

The TypeScript frontend already provides a bounded movement step for non-pointer button activation. Yew, Leptos and Dioxus web now route click events with browser `detail == 0` to a shared 32-unit movement step, clamped to the court, only during live play and never scripted replay. Pointer clicks (positive detail) stay on the existing pointer ownership path; keyboard hold handlers continue to prevent native button activation. Dioxus desktop's serialized event data does not expose the detail required to distinguish pointer clicks, so its non-pointer activation remains unimplemented.

The shared model suite passed 19 locked offline tests, including movement, bounds, paused/ready and scripted-replay lockout. Yew, Leptos and Dioxus web built for wasm32 with locked offline dependencies; Dioxus desktop `cargo check` passed. In localhost browser automation a 200ms Space hold on focused Up moved the SVG paddle: Yew 205 → 107.083206, Leptos 205 → 99.24986, Dioxus 205 → 110.99988. This confirms the existing hold path still runs, not the new non-pointer click path. Assistive-technology activation, pointer-versus-non-pointer discrimination in a real browser, physical input, Dioxus desktop and release qualification remain unverified.
