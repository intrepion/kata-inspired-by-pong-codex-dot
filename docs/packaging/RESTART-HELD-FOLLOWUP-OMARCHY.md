# Restart held-input follow-up — Omarchy, 2026-11-13

The GTK, Slint and GPUI frontends use `pong-gui-support::Model`. A model regression showed that R restarted during play while W remained active. Suppressing currently held movement on R now requires release and a fresh press. The regression failed before and passed after; all 13 model tests pass with locked offline dependencies. Actual native input and rebuilt toolkit clients were not tested.

Pixels and raw wgpu independently had the same defect for Enter and R. In each adapter an event-level regression failed before and passed after clearing movement on restart. Locked offline tests passed: Pixels 10, raw wgpu 9. These tests call the adapters' key handlers; they do not exercise a physical window or keyboard. Other native adapters with direct restart handlers still require audit; this is not a repository-wide clearance.

Yew, Leptos and Dioxus web builds containing the previous shared web fix were served via localhost and exercised through supported browser automation. A held W moved the paddle and subsequent Enter on Start / Restart returned it to center. The automation serialized the attempted overlapping key presses: explicitly observed in Leptos and Dioxus, the W hold had already finished when restart was sent. Thus these checks **do not** establish keyboard-held-through-restart behavior or pointer ownership through restart. The shared model regression remains the evidence for that case; a real overlapping input test remains open. No synthetic event injection was used.
