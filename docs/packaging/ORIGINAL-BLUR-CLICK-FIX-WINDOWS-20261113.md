# Original browser blur-click gate: Windows tests

After a blur or while the document is hidden, queued Start and Pause clicks could change game state even though the keyboard handler was gated. The click handlers now ignore activation while the recorded window focus is lost or the document is hidden. The internal blur/visibility pause path remains active. When focused and visible, pointer-style and non-pointer click activations use the existing behavior, including browser-generated keyboard or assistive activation; the gate does not inspect click `detail`.

A synthetic DOM regression failed on the previous checked-in JavaScript and passed after the change. It covers blurred and hidden Start/Pause clicks, blur/visibility pause, focused click events with detail 1 and 0, and the focused Space keydown path leaving native button activation unprevented. On Windows Node v24.20.0 all 27 checked-in JavaScript tests passed. The same regression also passed against the TypeScript source after Node's experimental type stripping; this is execution of stripped source, not TypeScript type-checking or a pinned `tsc` build. The pinned TypeScript compiler was unavailable and was not installed. Isolated baseline, candidate, test harness, stripped-source output and baseline failure remain in sibling workspace directory `original-blur-click-draft-windows-20261113`.

These are mock DOM results. Actual browser focus-event ordering, first activation after focus return, keyboard behavior, assistive technology, touch and physical input remain unverified. A fresh pinned TypeScript build, browser interaction and release qualification remain necessary. Existing historical evidence is unchanged.
