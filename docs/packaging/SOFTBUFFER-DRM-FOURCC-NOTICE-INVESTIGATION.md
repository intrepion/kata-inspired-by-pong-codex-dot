2026-11-13, Omarchy ARM64. The prior notice scan reports one package with no discovered notice file for the softbuffer graph: `drm-fourcc` 2.2.0. This remains a packaging review gap, not a finding that distribution is unlawful.

The cached crates.io archive has SHA-256 `0aafbcdb8afc29c1a7ee5fbe53b5d62f4565b35a042a662ca9fecd0b54dae6f4`, exactly matching `experiments/softbuffer/Cargo.lock`. Its normalized and original Cargo manifests declare `MIT` and list Daniel Franklin as an author, but the extracted package contains no conventionally named license, notice, copyright or copying file, and no explicit `license-file` declaration. `.cargo_vcs_info.json` records upstream revision `7b9f80060ffd4b35cd236437e65a17fb517d163c`. The exact upstream repository revision could not be verified in this investigation: the web fetch was restricted and the connected GitHub commit lookup returned a validation error. This does not establish that the repository or its license file is absent.

`cargo tree --offline --locked --manifest-path experiments/softbuffer/Cargo.toml --target aarch64-unknown-linux-gnu -i drm-fourcc` shows `pong-softbuffer -> softbuffer 0.4.8 -> drm 0.14.1 -> drm-fourcc 2.2.0`. This establishes a resolved target dependency, not proof of which code survives linking. The crate's own documentation says its enums are generated from Linux DRM's canonical header as of kernel 5.10. The [Linux v5.10 header](https://raw.githubusercontent.com/torvalds/linux/v5.10/include/uapi/drm/drm_fourcc.h) carries an Intel copyright and permission notice. Whether and how that notice applies to the generated portions needs source and distribution review; the version used to generate the published crate has not been independently established.

Do not fill the gap with a guessed copyright or generic license text, or mark the archive ready for redistribution. Next steps are to obtain and verify the exact upstream revision and its license/attribution, review generated-source provenance and other native/system-library obligations, then produce and verify a notice-bearing package.
