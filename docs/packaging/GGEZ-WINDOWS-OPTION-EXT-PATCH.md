# ggez Windows option-ext replacement

The Windows ggez graph reached MPL-2.0-declared `option-ext@0.2.0` through `ggez -> directories -> dirs-sys`. The existing vendored ggez implementation needs `directories` for project paths. Rather than remove the adapter or alter Windows known-folder behavior, this change adds a ggez-scoped local patch of `dirs-sys@0.5.0`, whose upstream package declares `MIT OR Apache-2.0`. It retains both upstream license files and provenance; [patch details](../../vendor/dirs-sys-ggez/PATCH.md) describe the small source change and maintenance scope.

The only `option-ext` use in upstream dirs-sys is an `Option<&str>` comparison in the Unix XDG directory parser. The patch replaces it with `user_dir == Some(key)` and removes the dependency and unused extern declaration. It adds a Unix-only parser regression for unspecified, matching and nonmatching keys. The Windows known-folder code is unchanged. The patch is selected only by the ggez workspace. Cargo's lock regeneration also changed `windows-sys` selections for `errno`, `rustix` and `winapi-util` from 0.61.2 to 0.52.0 without changing those packages' versions; cross-platform review is required.
