# Windows Tauri parser feature investigation

The four MPL-2.0-declared parser packages in the [Windows Tauri fixture](TAURI-WINDOWS-DIRS-PATCH-PROBE.md) were traced through the pinned local Tauri 2.12.5 / tauri-utils 2.10.2 graph. `tauri-utils` has an optional `dom_query@0.28.0` dependency, but its `build-2` feature enables `html-manipulation-2`, which enables `dom_query`. Both Tauri's own build dependency and `tauri-codegen` request `build-2`; `tauri-build` also requests it. `dom_query` normally depends on `cssparser` and `selectors`, and `cssparser` normally depends on `dtoa-short`. `cssparser-macros` is optional in cssparser itself, but the feature tree shows cssparser defaults enabled through dom_query and selectors, activating the macro. Cargo features are additive; a top-level opt-out cannot cancel a downstream request.

A separate task-local fixture used `tauri = { version = '=2.12.5', default-features = false, features = ['wry', 'custom-protocol'] }`, `tauri-build = { version = '=2.7.4', default-features = false }`, and the existing dirs-sys patch. It did not depend on the shared native-web library or either desktop wrapper. Its new offline Windows-filtered metadata graph had 234 resolved nodes; `option-ext` was absent but `cssparser@0.37.0`, `cssparser-macros@0.7.1`, `dtoa-short@0.3.5` and `selectors@0.38.0` remained. The inverse feature tree still showed `build-2 -> html-manipulation-2 -> dom_query`. Its locked offline Windows MSVC `cargo check` passed for a minimal program constructing a Tauri builder, and the build compiled the parser crates. The fixture lock SHA-256 is `54fa5854c3f908fd627aa6d3e2229ec908b03032c1e371fbc9ee03308117465c`; the fixture, metadata, feature trees and target are retained under task workspace `tauri-min-features-windows-20261113`.

This test rules out the specific top-level default-feature reductions tried; it is not an exhaustive search of future Tauri versions or alternative frameworks. The pinned code generator uses `tauri-utils::html2` to parse and serialize HTML and to process CSP nonce-related content. Replacing that parser would require a compatible Tauri dependency or maintained upstream change and tests for generated assets, CSP, both desktop wrappers and platform behavior. Removing HTML or CSP handling merely to drop a dependency would not be a validated substitution. No such rewrite, feature change, wrapper lock change, desktop executable or package was produced. The fixture's successful check does not test WebView behavior or satisfy the owner's strict no-MPL constraint; no release or legal clearance is claimed.
