# Swift collision timing fix: macOS model evidence

2026-11-13. The independent Swift core previously checked ball and paddle end-of-step positions and did not advance the remainder after contact. On macOS ARM64 the pre-fix standalone Swift regression reproduced both false hit and missed hit at both paddle faces; it also failed moving-player and post-contact wall/remainder cases. The shared core now informs the Swift fix: evaluate ball and paddle positions at face crossing, account for a preceding wall reflection, use the contact-time offset for rebound, then advance and reflect during the remaining time. This does not change the shared Rust physics.

Using Apple Swift 6.4.2 and isolated writable module cache, the checked-in standalone `scripts/swift-collision-smoke.swift` compiled against changed Game.swift and existing TouchInput.swift and passed 13 checks: crossing miss/hit and preceding/following wall on both sides; moving player, remaining travel, moving CPU; and both winning-score held-touch sequences. The pre-fix harness failed eight checks before the fix (the later added moving-CPU and winning-score checks were not part of that pre-fix run). Focused XCTest cases in `experiments/native-swift/Tests/PongCoreTests/CollisionTests.swift` were initially added but could not be run through SwiftPM here: SwiftPM's nested sandbox failed with `sandbox_apply: Operation not permitted`, and separate direct XCTest compilation could not find the Swift assertion APIs. No sandbox protections were disabled. The existing match-end test at 2468cea was exercised as equivalent standalone model logic, not as XCTest.

The fixed-seed `scenarios/smoke-v1.txt` Swift model replay produced 13 records before and after, with identical scores and states at every checkpoint. Ball values changed at ticks 600, 720, 840, 960, 1080, 1200 and 1440, and paddle values at 960 and 1080. This is model replay, not an app capture or device test; historical iOS captures and telemetry were not replaced.
