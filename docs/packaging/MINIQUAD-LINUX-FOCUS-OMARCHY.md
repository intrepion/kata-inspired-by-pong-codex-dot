# Miniquad focus gate investigation — Omarchy, 2026-11-13

Miniquad 0.4.11 reuses its minimized/restored callbacks for focus changes. Its macOS backend also calls the loss callback on a window move without a matching restore from that move; its Windows backend also uses these callbacks for minimize/restore size events. Treating these callbacks as unambiguous focus state on those platforms could disable controls after an ordinary move or reopen the gate while still unfocused. No new durable keydown gate is applied on macOS or Windows; the earlier pause/clear behavior remains. A reliable platform signal and cross-platform testing are still needed there.

On Linux, the inspected 0.4.11 X11 focus-in/focus-out and Wayland keyboard-enter/leave paths produce paired callbacks. The Miniquad frontend now gates live keydowns after a reported loss until restore on Linux only. Its initial assumption remains focused until a callback. The unit regression failed before the gate and passes afterward; it checks ignored pause/restart actions, restoration, and that an ambiguous callback does not close the gate. All 14 locked offline tests passed. This is an adapter/policy check, not physical input or OS focus-delivery verification.
