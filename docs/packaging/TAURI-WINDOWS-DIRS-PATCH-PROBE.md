# Windows Tauri dirs-sys patch feasibility

The existing locked Windows normal/build trees for `experiments/yew/desktop` and `experiments/leptos/desktop` both contain MPL-2.0-declared `option-ext@0.2.0` via `dirs-sys@0.5.0` and `dirs@7.0.0`, including paths through Tauri and Tauri build dependencies. This is a dependency-tree observation, not a final linked-code conclusion. Neither desktop manifest or lock was changed in this investigation.

A separate task-local fixture depended on the actual `pong-native-web-demo` library and selected the existing ggez-scoped `vendor/dirs-sys-ggez` 0.5.0 patch via its own `[patch.crates-io]`. It used a newly generated offline fixture lock (SHA-256 `2c8dd84bf2414ed8f012100f1cb5e0c96b63def5c7babed654f8f5c3423ae51a`), not either desktop's lock. The library source Git blob was `df749b91ae59447276fd6eb3e537b84989a9833a`; the patched XDG source blob was `4ac9d5f69a14da02fecba767db256046e1454f3e`. Windows-filtered offline metadata contained 244 resolved nodes and no `option-ext` package. Four MPL-2.0-declared packages remained: `cssparser@0.37.0`, `cssparser-macros@0.7.1`, `dtoa-short@0.3.5` and `selectors@0.38.0`. The Windows compile output showed the parser and selector crates compiled during the build; this does not establish final executable inclusion.

Using Rust 1.99.1 Windows MSVC, the fixture passed offline locked `cargo check` and both existing `pong-native-web-demo` library tests. No desktop executable, WebView, browser interaction, release build or package was tested. Fixture manifest, lock, metadata and build target remain under task workspace `tauri-dirs-sys-patch-probe-windows-20261113` and contain local paths; they are not published. Prior artifacts are preserved.

The fixture shows that the small patch is compatible with this Windows shared-library build, not that applying it to either separately locked wrapper is safe or sufficient. The four remaining MPL-declared dependencies, each desktop's actual lock and feature graph, native/system libraries, clean-machine operation and accessibility still require review under the owner's strict constraint. Concurrent ggez Linux and Mac rechecks later validated the XDG parser after a test-only module rename; this fixture predates that rename and neither Tauri desktop was rechecked on Unix. No adapter was removed, no wrapper patch was applied, and no compliant or release-ready claim is made.
