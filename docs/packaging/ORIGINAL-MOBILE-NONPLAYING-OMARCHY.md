# Original browser and mobile non-playing input review

2026-11-13, Omarchy ARM64. The original `game.ts` accepts document movement-key, movement-button and court-drag starts only in Playing; pause, focus loss and restart clear active controls, and keyboard repeats do not rearm them. No production defect was confirmed in these paths. The existing DOM-simulation test was expanded to press W, a movement pointer and a drag while Ready, start and deliver a repeat/continuing drag, and assert no paddle movement; it also exercises a new S press, pointer and drag during Paused followed by resume. All 24 original-game Node tests pass after `npm test` rebuilt `game.js`. These are simulated DOM events, not browser pointer or physical input. Over-state input is covered by the same source guard but was not separately driven to game over by the added DOM test.

The original page was served on `127.0.0.1` and opened in the in-app browser; automated Start and Pause clicks displayed the corresponding playing and paused UI. This is a bounded browser check, not a held-key, touch, device or physical-input test.

The Tauri mobile shell uses `clients/web-wasm`; its independent keyboard and pointer gates were fixed and checked separately in [the web/Godot report](WEB-TERMINAL-GODOT-NONPLAYING-OMARCHY.md). New mobile shell builds and device checks remain open.

A new JVM regression in `TouchInputTest.kt` covers gestures begun in Ready, Paused and Over, start/resume, stale move and fresh down.
