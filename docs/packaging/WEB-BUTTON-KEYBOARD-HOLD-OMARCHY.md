# Web movement button keyboard hold — Omarchy, 2026-11-13

The shared web controller and Yew, Leptos and Dioxus adapters support holding Space or Enter on a focused movement button. Key ownership is independent of pointer IDs and of the W/S and arrow bindings. Release or button blur clears its keyboard hold; pause and match restart clear all holds. Repeat keydown cannot reacquire a hold after a pause. Pointer controls retain their existing ownership rules. Button activation keys do not reach the root pause/restart shortcuts. Scripted replay remains input-locked.

Validation on Omarchy: `cargo test --offline --locked --manifest-path experiments/web-ui-common/Cargo.toml` passed 17 tests, including movement, multiple keys, pointer independence, blur, pause, repeat and restart. All three WASM targets built with locked offline dependencies; Dioxus desktop `cargo check --offline --locked --no-default-features --features desktop` passed. These are model and compile checks, not native interaction.

The matching wasm-bindgen 0.2.130 generated browser outputs served through 127.0.0.1. Supported browser automation held a focused button key for 250 ms, then observed the SVG paddle remain at the same position 300 ms after release. Yew down/Space moved y=205 to 326.41638; Leptos up/Space moved y=205 to 83.583176; Dioxus up/Enter moved y=205 to 79.66651. Each remained Playing. Browser observation does not establish physical keyboard behavior or desktop wrapper qualification. Blur/pause interactions were checked at the shared model level, not as held-key browser focus transitions.
