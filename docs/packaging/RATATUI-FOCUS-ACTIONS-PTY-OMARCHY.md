# Ratatui queued actions after focus loss — Omarchy, 2026-11-13

Ratatui paused and cleared movement on a terminal focus-loss event but continued to accept queued keys. It now ignores keys until a focus-gain event, while resize still pauses and clears movement without changing the focus gate. Startup retains the previous assumption of focus until a focus-loss event. Terminals that report a focus loss must report the corresponding gain before keyboard input resumes.

The extended PTY harness reproduced the defect against a fresh baseline: synthetic focus loss followed by Space changed the displayed state from Paused to Playing. After the fix, enhanced-key and fallback PTY runs both confirmed that synthetic focus loss followed by Space, R and Q kept the process paused and alive; a synthetic focus gain then allowed Space to resume. Both modes exited normally with Q and restored terminal attributes. The enhanced run also covered held movement, repeats and PTY resize; the existing enhanced overlapping-direction/alias PTY check passed. All 11 offline locked adapter unit tests passed.
