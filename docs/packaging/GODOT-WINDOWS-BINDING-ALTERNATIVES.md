# Windows Godot binding alternative investigation

The current `pong-godot` extension uses `godot = '=0.4.5'` with `default-features = false` and `api-4-5`, and requires Godot 4.5 or newer in its GDExtension descriptor. The [Windows link-map audit](GODOT-WINDOWS-MPL-LINK-INVENTORY.md) attributes object symbols to `godot-cell`, `godot-core` and `godot-ffi` 0.4.5, each MPL-2.0-declared. In the cached 0.4.5 manifest, `godot-core` and `godot-macros` are unconditional dependencies of `godot`; changing optional Godot API/code-generation features does not remove the core binding itself.

With the isolated Godot Cargo cache, offline locked Windows MSVC `cargo tree -e normal,build --prefix none --format '{p}'` was run for the actual manifest both normally and with root `--no-default-features`. Both commands succeeded and produced 48 identical lines, including `godot`, `godot-core`, `godot-ffi`, `godot-cell`, `godot-codegen`, `godot-macros` and `gdextension-api`. The raw tree SHA-256 for each is `bf70475f1457afd1756cde55be757a62cb007da687deeaed57503f4ce1b79016`; outputs under task workspace `godot-binding-features-windows-20261113` include local paths and are not published. This tests the existing configuration and one root feature switch, not every possible alternative configuration.

The official upstream manifests for [0.4.5](https://github.com/godot-rust/gdext/blob/v0.4.5/godot/Cargo.toml), [0.3.5](https://github.com/godot-rust/gdext/blob/v0.3.5/godot/Cargo.toml) and [0.2.4](https://github.com/godot-rust/gdext/blob/v0.2.4/godot/Cargo.toml) each declare MPL-2.0; the sampled older manifests also do not list the current `api-4-5` feature. This is not an exhaustive audit of all historical or third-party bindings, nor a claim that an earlier API feature could never run on a newer engine. The upstream [gdnative binding](https://github.com/godot-rust/gdnative) is MIT-declared but documents support for Godot 3, not Godot 4, so it is not a demonstrated drop-in for this Godot 4.5 project.

A different route is the official [Godot C++ GDExtension binding](https://github.com/godotengine/godot-cpp/tree/4.5), whose [4.5 branch license](https://github.com/godotengine/godot-cpp/blob/4.5/LICENSE.md) is MIT. This is a candidate for separate investigation, not a tested Rust binding or a substitution performed here. The current adapter directly owns the shared Rust `Game`, exposes start, step, pause, snapshots and scripted capture/report methods to GDScript; preserving that design with C++ would require an explicit Rust/C ABI and lifetime/error boundary, equivalent replay and input tests, and a separate audit of the selected binding, engine, export template, certificate bundle and system dependencies. A pure GDScript rewrite would instead duplicate the shared game model and would need determinism and behavior verification.

No supported feature or sampled older `godot-rust` version was found that removes the identified MPL binding while retaining the current implementation. No binding, engine setting, source, binary or package was changed. Other versions and bindings, engine CA-certificate configuration, actual exported-template contents, native input, clean-machine operation and the owner's strict license condition remain open. No replacement or release is claimed.
