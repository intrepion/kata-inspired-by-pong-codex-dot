# Windows WebView2 scripted shutdown probe

On 2026-11-13, the previously qualified Yew native executable from source `173c0ef1ea933479159e561a97028a4aa1118f67` (SHA-256 `7d39cfab79c32de3827b77a4063fa7aa05c359448ddf1626af354318205f3b98`) was compared with an isolated experimental Windows MSVC debug build. The probe changed only the shared native demo's scripted completion from `app.exit(0)` to requesting `close()` on the main webview window, and renamed the local probe package to avoid replacing the earlier executable. The probe source snapshot was `c659a8c368325e4b2d9542c61075ea90b04e1868`; its relevant application and shared controller source was unchanged from the original build apart from that probe. Probe executable SHA-256: `520bc264725a320018ffe8236cba897469643b767906d1c29b84e9fb8525990c`. Both embed the same Yew WASM SHA-256 `ed10fe83988ea5c550a5e8e788183ca418897d720db7ef49fa7e90a30dd4cd17`.

The initial close-window probe exited 0, generated six SVG sources and 13 reference-matching state records, with empty stderr. Two further alternating pairs ran the original and probe without scene output. All four exited 0 and their 13 states matched the reference. Both original runs logged `Failed to unregister class Chrome_WidgetWin_0. Error = 1412`; both probe runs had empty stderr. Logs, source snapshot, generated scenes and both distinct binaries are retained in local `webview-close-probe-20261113` and `web-pause-windows-c77` directories.

This bounded observation associates the diagnostic with the tested scripted shutdown paths on this host; it does not identify WebView2's internal cause, prove absence of other errors, or qualify normal window-close behavior. No production shutdown code was changed: last-window lifecycle and export semantics need cross-platform verification before adopting the probe. Normal desktop interaction remained blocked by the prior approval timeout and was not retried. Physical input, full match and release qualification remain open.
