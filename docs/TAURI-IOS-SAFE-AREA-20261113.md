# Tauri iOS bottom strip investigation

On 2026-11-13, an iPhone 16 Pro iOS 18.4 simulator loaded the web frontend from source `2c414fb68f47b777c961bc1b79eb990148cfa309` over `http://127.0.0.1:5188`. `cargo build --locked --offline -p pong-wasm --target wasm32-unknown-unknown` succeeded; the served debug WASM SHA-256 was `8684460759876ea29ae9eb0e3e26cabb2d9d15e2556611183675927b84c379cd`. The server logged HTTP 200 for the page, CSS, JavaScript and WASM. Device Hub showed the Ready court, with a white strip beneath the dark page at the home-indicator edge. This used the previously built Tauri development shell, not a shell rebuilt at that revision; its executable SHA-256 was `d6dfaf1713e55794888aaf03d0e79c80d4a70901766e97d1bad07752731f64ba` and debug dylib SHA-256 was `1de6a30f100d01422d4d81c726af737b1d3339e5871003c3933a2496353282e4`.

For a local diagnostic only, overriding the root page background to red changed the page area to red while the bottom strip stayed white. The override was removed afterward. This indicates that the visible strip is outside the page-painted area in this shell; it does not establish which native view or inset owns it. The checked-in Tauri configuration does not set a background color, and the locally cached Wry iOS implementation has a native background-color path. A follow-up isolated development shell built successfully from the same source with window `backgroundColor` set to `#0c211e`. On iPhone 16 Pro / iOS 18.4, Device Hub showed the Ready court with the white bottom strip gone in portrait and a dark background in landscape. Landscape controls were clipped at the bottom; an attempted start tap did not change the Ready state, so gameplay was not verified. The tested shell debug dylib SHA-256 was `25eb14d320b837b60a9310de156ce52eb2aa2a3e561212fe381285bbb3ea2f4a`; its executable SHA-256 was `d6dfaf1713e55794888aaf03d0e79c80d4a70901766e97d1bad07752731f64ba`. The build used the existing dependency cache and a separate Xcode output directory.

This was a visual simulator diagnostic, not a physical-device, full-match, simultaneous-touch, release-package, or release-shell qualification. No system security settings were changed. The loopback server was stopped and simulator data preserved.
