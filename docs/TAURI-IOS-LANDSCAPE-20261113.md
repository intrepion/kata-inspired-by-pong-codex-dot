# Tauri iOS landscape layout follow-up

On 2026-11-13, the iPhone 16 Pro / iOS 18.4 simulator ran the debug shell described in [the background investigation](TAURI-IOS-SAFE-AREA-20261113.md), serving the web frontend and WASM built from source `2c414fb68f47b777c961bc1b79eb990148cfa309` via localhost. The original 65vh landscape court pushed the controls partly below the visible screen. Reducing the landscape court maximum height to 40vh kept the court, all four buttons, instructions and home indicator visible in Device Hub. The tested stylesheet SHA-256 was `f386d6d594ea82076d0946136c94fdaa3ddee07352c7a1f5337485b2ec17786f`. The landscape media query does not apply in portrait.

A Device Hub click on Start reached Playing and CPU scoring in landscape. A later click on Pause did not visibly pause in this run; the cause and event delivery were not established. Earlier portrait clicks also did not visibly start, so portrait input remains unresolved rather than a confirmed application defect. The earlier load initially displayed Loading despite HTTP 200s, then reached Ready after a delay. Separately, `node --test tests/wasm.test.mjs` passed two ABI/determinism tests; those model tests do not establish native input delivery.

This is one simulator and viewport, not physical touch, accessibility, full-match or release qualification. Other landscape sizes, portrait input and pause/resume require further checking.

## Simulator input diagnostic

A follow-up used the same installed debug shell and localhost WASM with an isolated, temporary page-event readout. In portrait, two Device Hub Start attempts ended with `pointerup` targeted at Start, no observed `click`, and Ready. The first readout updated the DOM synchronously during events, so it could itself have affected click synthesis. With a revised readout deferred by 500 ms, a landscape Start attempt produced a `click` targeted at Start and Playing; a Pause attempt ended with `pointerup` targeted at Pause and no observed click. A further temporary probe avoiding unchanged status writes still ended one landscape Start attempt at pointerup without an observed click. The final diagnostic JavaScript SHA-256 was `f862a4b85913b8aff35d6ec52cf3a18a7738bfcc30db8e9d6650b0763a004ba1`; it was not shipped. The diagnostic readout can still affect event timing, and these observations do not isolate WebKit, Device Hub automation, or application behavior. No handler fix is claimed. Independent XCTest and physical-device checks remain needed.

## Independent XCTest follow-up

An independent Xcode UI test launched the installed Tauri shell against the uninstrumented localhost frontend on iPhone 16 Pro / iOS 18.4. It waited for Ready, then tapped the accessible Start, Pause and Resume buttons and observed Playing, Paused and Playing. `testStartPauseResume` passed in 33.026 seconds (one test, zero failures), with result bundle retained locally at `/tmp/pong-tauri-input-xcui-20261113.xcresult`. The separate [XCTest probe](../clients/tauri/ios-ui-probe/README.md) contains the test and setup instructions. The frontend was from `2c414fb68f47b777c961bc1b79eb990148cfa309` with the 40vh landscape stylesheet subsequently published at `7e309c53f6bc385863af41179dba5ab11cbd5e79`; app.js SHA-256 `72c7110b9efc7164ee6bd702ce132ac160097142c04103e98eb315b0dc8c6fb7`, stylesheet `f386d6d594ea82076d0946136c94fdaa3ddee07352c7a1f5337485b2ec17786f`, WASM `8684460759876ea29ae9eb0e3e26cabb2d9d15e2556611183675927b84c379cd`. The installed shell is the debug build described in the background investigation. This independent simulator result shows these sequential controls worked under XCTest, not that the earlier Device Hub failures are explained or that physical/simultaneous touch, full matches, and release builds are qualified.

## Simulator match and restart

The independent `testMatchOverAndRestart` started an unattended normal match, waited for the accessible Match over status, tapped Start / restart, and observed Playing again on the iPhone 16 Pro / iOS 18.4 simulator. The retry passed in 70.509 seconds (one test, zero failures), with result bundle `/tmp/pong-tauri-match-retry-xcui-20261113.xcresult`. It does not assert the final score, reset score or winner. An earlier attempt failed after the Start button did not appear within 60 seconds; the server logged the remaining frontend assets immediately after the timeout. That failed result is retained at `/tmp/pong-tauri-match-xcui-20261113.xcresult`; the retry extended the button wait to 120 seconds. Both used the same installed debug shell and uninstrumented localhost frontend documented above. This is an automated, unattended simulator match, not physical input, a human-played match or release qualification.
