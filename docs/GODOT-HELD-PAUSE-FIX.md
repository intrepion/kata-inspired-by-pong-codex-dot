# Godot held movement across pause

On Omarchy ARM64, Godot's polled movement continued immediately on resume when a movement key stayed held across an explicit pause. A headless scene test using `Input.parse_input_event` reproduced the problem before the fix: W moved the player after pause/resume, and the regression test exited 1. This is synthetic engine input, not native or physical keyboard delivery.

The adapter now suppresses each held movement binding on a transition from Playing to Paused, until release. Focus loss also suppresses currently held movement before pausing. A fresh alias remains independent; key releases and polling clear suppression. With the fix, `input_smoke.gd` passed for W, Up, S and Down crossed with Space, Enter and P, checking pause, no stale movement, release and renewed movement, plus an independent fresh alias. Focus-loss delivery itself was not exercised. Existing headless extension/start/move/pause/resume/reset smoke passed, and a separate headless scripted replay produced 13 records identical to `evidence/rust-core-contact-timing-model-20261112.jsonl`.
