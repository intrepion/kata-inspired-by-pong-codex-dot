A distinct mobile case remains to reproduce. Android's `MainActivity` pause button toggles the game without clearing `PongView.touch`, whose `targetY` feeds the next game step. Swift's pause button likewise toggles the game while `touchY` remains the timer's movement target; backgrounding does clear it. If a court gesture remains active while a second interaction pauses and resumes, the retained target could move the paddle immediately on resume. This is an inference from source, not a demonstrated device or simulator failure. Existing mobile tests cover separate pause/resume and touch-release behavior, not this combined gesture. Android and iOS workers should first reproduce it with a held court gesture and separate pause interaction, then test release/cancellation and a fresh gesture when fixing it; avoid assuming that clearing a value alone prevents a continuing gesture callback from restoring it.

The Omarchy environment had no `java`, `gradle`, or `kotlinc` on PATH during this review, and no Android or iOS test was run. No mobile code or artifacts were changed. Separately, `node --test scripts/packaging/*.test.mjs` passed all three packaging test files on Node `v26.12.1`; this is a local regression check, not installation, notice completeness or release qualification.
