# Native build evidence producer (local review candidate)

`produce.py` is an unwired foundation for Ratatui on Linux ARM64 GNU, macOS ARM64 or Windows x64 MSVC, Windows Softbuffer, and macOS ARM64 SDL3. It refuses unsupported pairs and cross-target execution. It requires a new output directory outside the source checkout, a full trusted expected commit and tree, and a Git checkout clean of tracked, untracked **and ignored** files. It verifies the checkout root, commit, tree and cleanliness before and after collection.

The producer identifies the selected `rustc` sysroot, invokes that sysroot's `rustc -vV` and `cargo --version`, forces Cargo to invoke that compiler, and records hashes of both executable files and a deterministic digest of the selected target's sysroot library files. It explicitly sets both compiler-wrapper variables to empty, overriding configured wrappers, and clears Cargo target/build environment overrides. It compiles tests with Cargo `--no-run --message-format=json`, selects exactly one named adapter binary within the fresh target directory and invokes it directly. Cargo-configured target runners therefore do not execute the test binary. It uses a fresh target directory and locked offline Cargo commands. It hashes the resulting binary before and after executing its own bounded `--scripted-test`; at least one directly executed adapter unit test must pass, and 13 replay records must match the checked-in model reference within the repository's 0.001 numeric tolerance. Logs and a JSON evidence record are retained outside the checkout. A failure leaves no success record; partial files can remain for diagnosis and must not be silently reused.

This is evidence of the commands executed in that environment, not a cryptographic attestation or complete reproducibility proof. The target-sysroot digest does not cover every compiler dynamic library, linker, C compiler, environment or dependency; source-bound Rust/LLVM and Unicode notices still need authenticated inputs and independent assessment. Integration tests and doc tests are not collected by the direct adapter-unit-test path. The producer does not package, inspect binary imports, scan privacy, sign, certify license acceptability, or interact with a release. Windowed replay may fail or time out on hosted runners without suitable display access; that is a failure, not a physical-input test. Native uploads remain disabled.

Tests in `test_produce.py` use synthetic fake runners and fixture binaries. They do not execute a compiler, native build, GUI or network request. Run them with `python3 -m unittest discover -s scripts/release/native -p 'test_*.py'`.
