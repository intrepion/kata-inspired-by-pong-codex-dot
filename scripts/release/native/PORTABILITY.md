# Ratatui Windows review harness

The native and Windows directories form a local, fail-closed review harness. The bound producer is pinned to the explicit source commit and tree in `handoff.py`; update and independently review that pin and fresh notice evidence for any other source. The previous local binary and evidence belong to the previous harness and must not be relabeled.

The producer requires a fully clean source checkout, including untracked and ignored files. Run the harness from a separate location when evaluating an uncommitted patch, or from a committed harness against its separately pinned clean source checkout. The current pin predates this uncommitted harness.

Run portable fixtures with `python -B -m unittest discover -s scripts/release/native -p "test_*.py" -v` and the corresponding `scripts/release/windows` suite. The six live-evidence failure checks are optional: set `PONG_RATATUI_TEST_REPO` and `PONG_RATATUI_TEST_EVIDENCE` to an independently verified clean checkout and evidence generated by these exact harness bytes. They copy only evidence needed for the tests and never change those inputs. A prior harness evidence set is expected to fail code-digest validation.

`package_bound.py` obtains its executable and notice files only from validated schema-2 evidence. Its input manifest is a source-bound review supplement, not a final link map, attestation, or legal clearance. The Windows archive is unsigned; runtime compatibility, physical inputs and clean-machine behavior remain unverified. Privacy scanning requires explicit relevant workspace fragments and cannot prove absence of every possible private string.

The older standalone Windows helper retains its original source pin; the bound packager uses only its verification and ZIP mechanics and writes the source identity from the verified handoff. Do not run that helper unchanged to label another source commit.
