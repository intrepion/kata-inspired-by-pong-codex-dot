# Browser-only draft uploader review candidate

The workflow runs only by explicit `workflow_dispatch` from `main`, with a full source SHA that must equal the workflow run and checkout. The build job has read-only contents permission. It tests and packages first-party browser files, binds an archive digest to this run's output, and uploads the archive and checksum as a run-specific Actions artifact. The optional uploader defaults off, has `contents: write` and `actions: read` only in its own job, and downloads only the named artifact from the same run and attempt. It reads data from that artifact; it does not execute artifact contents.

The uploader validates the exact artifact and ZIP member allowlists, sizes, file types, internal and external checksums, source SHA and expected job digest before creating anything. It checks existing release and tag collisions and only creates a new draft prerelease with a tag derived from source SHA, run ID and attempt. It never adopts or edits an existing release, overwrites assets, calls a publish endpoint, or automatically retries an uncertain write. Before and after every asset upload it checks release identity, target, draft/prerelease state and the exact names, sizes and SHA-256 digests expected so far. A failed or uncertain write may leave a partial draft; inspect and resolve it manually. A subsequent run/attempt creates a different tag, never resumes or clobbers the old draft.

**Concurrency limitation:** GitHub does not provide an atomic "upload only while draft" precondition for the asset upload. Someone could publish between the last state check and the upload. The workflow concurrency group serializes this workflow's uploaders only; it does not lock the GitHub UI or other clients. The owner must not publish or otherwise edit the draft until the uploader has finished and its checks pass. This is an opt-in review candidate, not an absolute race-safety guarantee. Existing public releases must never be modified. This job should not be enabled until independent review, action-lock regeneration, and hosted validation are complete.

This builds and stages the browser package only. Native automation and the separate evidence preflight remain unwired. Automated checks do not establish physical input, clean-machine compatibility, complete attribution, or legal clearance.
